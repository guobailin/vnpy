# 甲醇数据层：tqsdk 长历史 + 自建后复权主力连续

`tq_data.py` 负责把「干净的长历史甲醇数据」灌进 vnpy 的 sqlite 库。起因是两条旧口径的硬伤：

1. **深度不够**：新浪免费分钟源每个周期硬顶 1023 根 → 15m 只有约 45 个交易日、5m 16 天、1m 3 天。
   用 45 天判断日内策略有没有 alpha，统计上等于掷硬币。
2. **主连被污染**：新浪的 `MA888`（内部映射 `MA0`）是**未复权拼接**，2026-09-10 21:15 一次性跳约
   300 点接上真实合约价位；任何用它的回测数字（含 -1.09% / -0.26%）都作废。

现在换成天勤（tqsdk）直连 + 自建连续，实测深度（本机 2026-09-26）：

| 周期 | 旧（sina） | 新（tqsdk，MA888 自建连续） | 倍数 |
|------|-----------|---------------------------|------|
| 1m | 3 个交易日 | **10000 根 / 30 个交易日** | 10× |
| 5m | 16 天 | **7818 根 / 112 天** | 7× |
| 15m | 45 天 | **11718 根 / 515 天** | 11× |
| 1h | 169 天 | **11605 根 / 1684 天（6.9 年）** | 10× |
| d | 污染拼接 | **1684 根 / 2019-10-22 起** | 口径修正 |

## 口径约定（写死，避免再踩）

- **时间戳一律取 bar 收盘时刻**：库内既有数据与 vnpy GUI 都是这个口径（15m 日盘为
  09:15…10:15 / 10:45…11:30 / 13:45…15:00）。tqsdk 原生给 bar 起点，本工具统一 `+ duration`；
  日线本身按交易日 00:00 标注，不再平移。已用重叠区间核对：时间戳是旧库的超集，收盘价差 ≤ 2 点（≤0.07%）。
- **夜盘归属下一交易日**：21:00–23:00 的 bar 属于下一个交易日。按日历日切分会把换月点切在夜盘中间，
  引入 18–36 点的假跳空。
- **拼接用价差（差值）法**：期货价格不是比例量；价差法保绝对变动，所以连续序列的**点数损益是真实的**，
  但历史段的**百分比收益会被平移扭曲**（这是价差复权固有的，不是 bug）。
- **默认锚定最新段**（`--anchor latest`）：最新一段价格 = 真实主力合约价格。
- **主力判定**：逐交易日取日线持仓量最大的合约，新合约需连续 `--confirm-days`（默认 2）日占优才换月。
- **volume / open_interest** 取当日主力合约的值，不跨合约求和。

## 用法

```bash
export TQ_USER=...  TQ_PASS=...     # 或放进 ~/.hermes/.env，用 --env-file 指定
python datafeed/tq_data.py probe  --product MA
python datafeed/tq_data.py pull   --product MA --durations d,1h            # 全量合约
python datafeed/tq_data.py pull   --product MA --durations 15m --limit 34
python datafeed/tq_data.py build  --product MA --intervals 1m,5m,15m,1h,d,w,1M,1Q --out-symbol MA888
python datafeed/tq_data.py verify --product MA --out-symbol MA888 --interval 15m
python datafeed/tq_data.py import --product MA --intervals 1m,5m,15m,1h,d,w,1M,1Q \
    --symbols MA888,CZCE.MA701,CZCE.MA610 --db ~/.vntrader/database.db --prune
```

凭证只从环境变量或 env 文件读，不落盘、不回显。`import` 前会自动备份目标库。

- `--prune`：删掉库里**不在本次缓存里**的旧口径行。同一 symbol 不能混两种拼接口径，否则回测会
  在换月处吃到假跳空。本次清理：MA888 共 1836 根（d 1167 / w 247 / 1M 58 / 1Q 20 / 1h 344），
  各真实合约 1h 共 1023 根。

## 校验

`verify` 是权威检查：换月处的**绝对价格变动**必须等于新合约在同一对时间戳上的绝对变动
（价差复权保变动）。当前实测：

| 周期 | 可校验换月点 | 最大点数差 |
|------|-------------|-----------|
| d | 21/21 | **0.0** |
| 1h | 21/21 | **0.0** |
| 15m | 8/21（其余超出缓存窗） | **0.0** |
| 5m | 3/21 | **0.0** |

`build` 输出里的「换月处相邻 bar 差 xx 点」是**粗口径**提示（含真实隔夜跳空），不要当拼接误差读；
MA 单日振幅均值约 73 点，隔夜跳 60–100 点属正常。

## 踩过的两个根因（不是表面坑）

1. **macOS 大小写不敏感文件系统 + vnpy 的 `1m` / `1M`**：缓存名 `*_1m.csv` 与 `*_1M.csv` 是同一个
   物理文件，月线覆盖了 1 分钟线，并把 1m 数据当「月线」写进库。修法：缓存名换成不撞车的 token
   （`min1` / `month1` …，见 `CACHE_TOKEN`）。凡是在 macOS 上用文件名承载大小写敏感标识符都会中这一枪。
2. **换月基准取错日子**：最初用「新段首个交易日」两个合约的价差做基准，等价于把基差**放大成两倍**
   假跳空（2026-09-11 处 364 点基差 → 实测 778 点跳空）。正确做法是用**旧段最后一个交易日**
   两个合约的收盘价之差。修完跳空降到 44–100 点（= 真实隔夜波动量级），`verify` 归零。

## 已知残留（有意保留，未清）

- 各真实合约的 **w / 1M / 1Q**（每个合约约 47–59 行）仍来自旧源：这些是从**该合约自己的日线**
  重采样的，与 888 污染无关，量级 ≤ 2 点。要彻底统一，需要 `build` 也按合约产出派生周期。
- `datafeed/cache/` 是可重拉的原始 K 线缓存（已 gitignore），不入库。
- `datafeed/cache_old_naming/` 是 1m/1M 撞名事件的隔离物，确认无误后可删。

## 数据到位后重跑的结论（先红后绿）

同一套策略、同一成本口径（`rate=0.0001` / `slippage=1 tick` / `size=10` / 本金 10 万），
样本从 45 天扩到 515 天（15m）与 1684 天（1h）：

| 样本 | 策略 | 有成本 | 零成本 |
|------|------|--------|--------|
| MA888 15m（515 天） | DualThrust | -12.43% | -2.01% |
| MA888 15m（515 天） | RangeReversion | **-25.93%** | **+3.67%** |
| MA888 1h（1684 天） | DualThrust | -13.73% | — |
| MA888 1h（1684 天） | RangeReversion | **-43.88%** | — |

两个读数变了：

- 「零成本仍亏」**再次被推翻**：RangeReversion 在 515 天零成本口径下是 +3.67%。问题不在信号方向，
  而在**换手**——2480 笔/515 天，1 tick 双边滑点就吃掉约 30 个百分点。
- 「45 天样本」确实不可信：同一策略 45 天给 -3.39%，515 天给 -25.93%（有成本）/ +3.67%（零成本）。
  用短窗口下结论是双向错的。

结论：**在 1 tick 双边滑点假设下，这两个日内框架在甲醇上没有可交易的正期望**；要救只能先降换手
（提高信号门槛 / 拉长持有），不是调参。
